캠핑가자는 공공 데이터로 모은 전국 캠핑장 정보를 바탕으로 예약, 결제, 리뷰, 채팅을 한곳에서 제공하는 캠핑장 예약 서비스입니다. 2026년 6월부터 7월까지 프로그래머스 데브코스 최종 프로젝트로 5명이 함께 만들었습니다.

저는 CI/CD와 인프라 구축, SSE 실시간 알림, 캠핑장 검색, 리뷰, 관리자 기능을 맡았습니다.

## 서비스

캠핑장 예약은 여러 플랫폼에 흩어져 있어서 이곳저곳 돌아다니며 찾아야 합니다. 캠핑가자는 고캠핑 API에서 전국 캠핑장 정보를 주기적으로 가져오고, 호스트가 자기 캠핑장의 구역(Site)을 등록해 예약을 받을 수 있게 했습니다. 사용자는 캠핑장을 검색하고 예약한 뒤 토스페이먼츠로 결제하고, 호스트와는 채팅과 알림으로 소통합니다. 선착순으로 싸게 예약하는 타임딜도 있습니다.

## 배포 자동화와 운영 환경

GitHub Actions로 테스트, Docker Hub 이미지 푸시, EC2 배포까지 이어지는 흐름을 만들었습니다. 배포한 뒤에는 헬스체크를 몇 번 다시 시도하며 서버가 제대로 떴는지 확인합니다.

CI에는 JaCoCo 커버리지를 PR 코멘트로 남기는 단계와 Checkstyle 검사, Gradle 캐시를 넣었습니다. 테스트도 보강해 62.9%였던 커버리지를 77.9%까지 올렸습니다.

운영 서버에서는 Nginx Proxy Manager 뒤로 백엔드 포트를 숨기고 HTTPS로만 접속하게 했습니다. 로그인 쿠키의 Secure, SameSite 설정은 로컬과 운영 환경에서 다르게 적용했습니다. 로컬에서는 Docker로 MySQL, Prometheus, Grafana를 한 번에 띄울 수 있게 구성했습니다.

## SSE 실시간 알림

예약 승인, 결제, 리뷰 알림은 서버가 사용자에게 보내기만 하면 되는 단방향 푸시라서 WebSocket 대신 SSE를 썼습니다. 접속한 사용자의 연결은 `ConcurrentHashMap`으로 관리합니다.

처음에는 알림 저장과 SSE 전송이 같은 트랜잭션 안에 있었습니다. 그래서 전송이 실패하면 알림 저장까지 롤백됐습니다. 전송을 `AFTER_COMMIT` 이벤트로 분리해 커밋된 알림만 보내도록 바꿨습니다. 또 승인과 결제 API가 푸시가 끝날 때까지 응답을 기다리고 있어서, 전송을 `@Async`로 비동기 처리했습니다. 이제 전송이 실패해도 알림은 DB에 남아 있어 나중에 목록에서 볼 수 있습니다.

## 캠핑장 검색

검색 조건은 날짜, 인원, 객실, 가격, 키워드입니다. 조건마다 `BooleanExpression`을 만들어 QueryDSL로 조합하고, 겹치는 예약 수를 빼서 남은 수량을 계산했습니다.

처음 쿼리는 서브쿼리가 겹겹이 중첩돼 있었습니다. 예약 가능한 캠핑장 ID를 먼저 뽑고 그 목록을 IN 절로 넘기는 두 단계로 나눠 중첩을 없앴고, 후보가 없으면 바로 빈 페이지를 돌려줍니다. 검색 결과에 붙는 이미지, 별점, 최저가는 IN 쿼리 세 번으로 묶어 가져와 Map으로 붙였습니다. 결과가 몇 개든 쿼리 수가 늘지 않습니다.

리뷰 최신순 조회는 복합 인덱스를 추가해 filesort를 없앴습니다. 리뷰 1만 건 기준으로 4.43ms 걸리던 조회가 0.04ms로 줄었습니다.

## 리뷰와 관리자 기능

리뷰는 이용을 마친 예약에만 작성할 수 있고, 캠핑장별 리뷰 목록과 내가 쓴 리뷰 목록을 만들었습니다. 관리자 기능으로는 대시보드 통계, 캠핑장 승인과 거절, 일괄 승인, 회원 목록 조회와 이용 정지를 만들었습니다.

## 기술

- **백엔드:** Java, Spring Boot, Spring Security, JPA, QueryDSL, SSE
- **데이터:** MySQL, Redis
- **인프라:** AWS EC2, RDS, S3, Nginx Proxy Manager, Docker, GitHub Actions, Prometheus, Grafana
- **외부 API:** 고캠핑 API, 토스페이먼츠
